## 🗂️ File Structure

```
bored-puzzle-project/
├── index.html       ← markup only — no inline style or script
├── style.css        ← all styling, CSS variables, animations
├── script.js        ← dot-grid canvas, ticker logic, game engine, A* solver
├── setup.js         ← Node script: reads .env → writes config.js (run once)
├── .env.example     ← committed template showing required key names (no values)
├── .gitignore       ← keeps .env and config.js out of git
```

**Not in git (gitignored — created locally):**
```
├── .env             ← your real API key (NEVER commit)

```

Clean separation of concerns — each file has one responsibility.  
API key never touches GitHub at any point.

## ✨ Features In Detail

### 🟡 Live Ticker
- Fetches from four API Ninjas endpoints randomly: `/facts`, `/jokes`, `/quotes`, `/trivia`
- Every new item is merged into a `localStorage` pool (`boredTicker_v3`) — grows over time
- On API failure the ticker silently falls back to the stored pool — users never see an error
- 28 built-in seed items so it works perfectly even with no API key
- Scroll pauses on hover via CSS `animation-play-state: paused` — no JS listener needed
- Auto-refreshes from API every 2 minutes silently in the background

### 🎮 8-Puzzle Game
- **Deterministic daily seed** — Game #1 is the same puzzle for everyone on the same calendar day
- **Sequential puzzles** — ➕ New advances through an infinite numbered series (seed = date × 1000 + gameIndex)
- **Reset vs New** — Reset restores the exact starting tile layout; New loads a fresh puzzle
- **Solvability check** — every board is validated before being shown (inversion-count parity)
- **Pop animation** — satisfying bounce on each tile slide
- **A\* Hint** — calculates optimal path and tells you the next tile to move; depth-capped at 32

### 📊 Persistent Stats

| Stat | Description |
|---|---|
| **Solved** | Total puzzles completed (cumulative across sessions) |
| **Best Time** | Fastest solve in seconds (personal record) |
| **Best Moves** | Fewest moves to complete a puzzle (personal record) |

All stats survive page refresh via `localStorage`.

### 🎨 Design System
- **Card style** — thick `2.5px` black border + `6px 6px 0` hard offset shadow, matching bored.com
- **Hover lift** — card translates `(-3px, -3px)` and shadow deepens to `10px 10px 0`
- **Same treatment** on tiles and buttons — consistent hard-shadow interaction language
- **Dot-grid background** — canvas-rendered, configurable via one CSS variable (see below)

## 🔑 API Setup (Secure — key never touches GitHub)

This project uses a **two-file pattern** to keep your API key out of git entirely:

```
.env          ← your real key  (gitignored — stays on your machine only)
config.js     ← generated from .env  (gitignored — browser reads this)
```

### Step-by-step

**1. Copy the template**
```bash
cp .env.example .env
```

**2. Add your key to `.env`**
```bash
# .env
API_NINJAS_KEY=aBcDeFgHiJkLmNoPqRsTuVwXyZ123456
```
Get a free key at [api-ninjas.com](https://api-ninjas.com/) — free tier is 10,000 requests/month.

**3. Generate `config.js`**
```bash
node setup.js
```
This reads `.env` and writes `config.js` — a browser-loadable file that exposes only the keys the app needs via `window.ENV`. It prints a masked confirmation:
```
  ✔  config.js generated successfully.

     Keys exposed to browser:

       API_NINJAS_KEY           aBcDeF…  (32 chars)
```

**4. Open the app**
```bash
# Simplest — just open the file
open index.html

# Or run a local server (avoids any CORS edge cases)
python -m http.server 8080
npx serve .
```

### Why not just put the key in script.js?

| Approach | Key in GitHub? | Safe? |
|---|---|---|
| Hardcode in `script.js` | ✅ Yes | ❌ Exposed publicly |
| Read from `.env` at runtime | N/A — browsers can't read files | ❌ Not possible |
| **This project's approach** | **❌ Never** | **✅ Safe** |

`config.js` is in `.gitignore` — it is generated locally and never pushed. Anyone cloning the repo runs `node setup.js` with their own key.

### What if I skip this step?

No problem. The app detects a missing key and silently uses the built-in seed pool (28 facts, jokes & quotes). Users see no error and the ticker still works.

## 🔧 Customisation

### Dot grid character — one CSS variable in `style.css`

```css
:root {
  --dot-char: '·';   /* ← change this */
}
```

| Value | Result |
|---|---|
| `'·'` | middle dot (default) |
| `'•'` | filled bullet |
| `'+'` | plus signs |
| `'×'` | cross marks |
| `'*'` | asterisks |
| `'–'` | dashes |
| `'✦'` | decorative stars |
| `'#'` | hash grid |

### Dot density and darkness

```css
:root {
  --dot-size:      20px;              /* grid spacing — smaller = denser */
  --dot-color:     rgba(0,0,0,0.30); /* opacity — higher = darker */
  --dot-font-size: 13px;             /* character render size */
}
```

## 🧠 What I Learned

### API & Resilience
- **Graceful degradation** — building a system that never exposes errors to users; offline = silent fallback
- Growing a `localStorage` cache from live API data and deduplicating entries across sessions
- **Secure API key handling for static sites** — the `.env` → `setup.js` → `config.js` pattern keeps secrets out of git while remaining fully functional without a backend server

### Algorithms
- **A\* search** from scratch — Manhattan distance heuristic, priority queue via sorted array, depth cap
- **Inversion count parity** — detecting unsolvable 8-puzzle configurations before display
- **LCG (Linear Congruential Generator)** — deterministic seeded shuffle for reproducible daily puzzles

### CSS Techniques
- `animation-play-state: paused` on hover — pausing a CSS `@keyframes` scroll with zero JavaScript
- Hard offset `box-shadow` as a complete design language (borders, hover states, buttons)
- CSS custom properties as a single-file theming system readable from JavaScript

### JavaScript
- **State isolation** — `boardSnapshot` vs live `board` so Reset restores layout without regenerating
- Reading CSS custom property values at runtime via `getComputedStyle`
- `ResizeObserver` to keep a `<canvas>` overlay in sync with a dynamically-sized page
- Clean module-like organisation across separated `style.css` / `script.js` files

### UX Thinking
- Reset = same puzzle, fresh attempt (muscle-memory replay) vs New = next puzzle (progression)
- Sequential puzzle numbering feels more intentional than random — users can say "I'm on puzzle 12"
- Solved / Best Time / Best Moves is more motivating than a streak for a casual puzzle game
